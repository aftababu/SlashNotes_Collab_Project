# Engineering Taste

- Eliminates disk I/O from UI rendering paths: cache file metadata (e.g., note headers, last-modified timestamps) in an in-memory index and render list items synchronously from cache, rather than per-item `File` stat calls inside composables (which cause recomposition lag/frame drops). Confidence: 0.85
- Runs all blocking/native calls (UniFFI/JNI, file system access) strictly inside `withContext(Dispatchers.IO)` — never on the main thread. Confidence: 0.95
- Invalidates in-memory caches on every mutation so cached data never goes stale after create/rename/delete/move operations. Confidence: 0.7
- Debounces and caches expensive per-keystroke work (e.g., markdown parsing) in an LRU keyed by content hash on a background dispatcher; the UI thread only does cheap cache lookups so typing and navigation never block. Confidence: 0.85
- Flattens and virtualizes large tree/list UIs into a single LazyColumn with lazy child loading instead of eager recursive nested composition, so only visible rows are composed. Confidence: 0.8
- Before changing rendering/parsing code, benchmarks or measures the actual cost (e.g., timing the Rust parser on a large document) to confirm which path is the bottleneck, rather than guessing. Confidence: 0.75
- Prioritizes config-level and build-system optimizations (R8/ProGuard minification, Rust LTO + strip + panic=abort, removing unused dependencies) before code-level micro-optimizations, because config changes carry near-zero regression risk and often yield the largest byte/RAM savings per effort spent. Confidence: 0.75
- Wants complete, untruncated, and actionable error messages with contextual detail (e.g., the file/repo path, the underlying cause, and the specific HTTP status code with what it means) so the user can self-diagnose what went wrong; generic or opaque messages (e.g., "connection failed or git not available") are reported as defects to fix. Confidence: 0.8
- Never swallows or replaces exceptions with a generic fallback message; propagates the real underlying error (including stripping framework wrappers like UniFFI's `msg=` prefix) so the user can see exactly what failed instead of a vague catch-all. Confidence: 0.75
- Maps raw error codes to actionable, human-readable hints (e.g., HTTP 401 → bad/missing token, 403 → insufficient scope or wrong URL, 404 → repo not found, 429 → rate limit, 5xx → server error) rather than surfacing raw library error text alone. Confidence: 0.75
- Keeps credential/auth handling consistent across all code paths (e.g., GitHub PATs always authenticate as `x-access-token`), so test/probe paths behave identically to the real sync path and don't produce divergent results. Confidence: 0.7
- Debugs Android issues via adb/logcat and expects errors to be logged visibly there; a failure with nothing showing in logcat is itself treated as a problem to diagnose. Confidence: 0.65
- Converts Android SAF `content://` URIs to absolute POSIX paths before passing paths through the UniFFI bridge to native code (Rust/libgit2), because native code cannot process `content://` URIs — raw URIs must never reach the native layer. Confidence: 0.9
- Validates directories before handing them to native code: ensures existence (mkdirs if missing), `isDirectory`, and `canWrite`, failing fast with an explicit user-facing error and stopping execution rather than letting native code fail opaquely. Confidence: 0.8
- Logs the exact normalized value at the FFI/UniFFI boundary so invalid inputs (e.g., raw `content://` URIs) can be confirmed to never silently reach native code. Confidence: 0.8
- Prefers embedded native libraries (e.g., libgit2 via git2 crate) over shelling out to external CLI binaries, since CLIs like `git` may not exist on Android. Confidence: 0.85
- Treats read-only/probe operations (e.g., a git "Test Connection" check) as non-mutating with respect to user data: never initializes a repo inside the user's real vault path. Prefer `Repository::discover` on the real path (which avoids libgit2's ownership check) or a disposable temp dir, since `Repository::init` on shared/external storage falsely fails with "path not owned by current user". Confidence: 0.75
- When overriding framework gesture handling in Compose, intercepts pointer events at `PointerEventPass.Initial` (tunneling phase) and calls `consume()` so framework components (e.g., `BasicTextField`'s internal `TextFieldSelectionManager`) never receive the gesture, preventing native popups/handles; a top-level guard consumes events for the whole drag to preserve pointer capture. Confidence: 0.75
- Uses `Modifier.imePadding()` as the single source of IME insets, flush against the keyboard with zero gap, avoiding hardcoded bottom padding inside scroll containers. Confidence: 0.7
- For custom Compose drag/selection gestures, owns the gesture with a single `pointerInput` on the container (viewport) in viewport-local coordinates and makes overlay handles visual-only (no `pointerInput` of their own); per-widget handlers report coordinates local to that small widget (e.g., a 36dp handle box), which breaks hit-testing and position tracking as the finger crosses widget boundaries (e.g., into the IME). Confidence: 0.7
- In Compose, when a long-lived effect/coroutine or `pointerInput(Unit)` handler reads state captured at composition, uses `rememberUpdatedState` to read fresh values instead of restarting on every change; otherwise the handler captures the initial (often empty/null) value forever and never sees later updates (e.g., an initially-empty handle-geometry list making hit-tests always miss). Confidence: 0.7
- When a custom auto-scroll loop drives selection, disables or guards competing view-elevation effects (e.g., `bringIntoView`) while the drag is active so they don't fight `scrollBy` every frame and cancel the auto-scroll. Confidence: 0.65
- For Windows releases, wants a proper installer that installs per-machine to C:\Program Files (C: drive) rather than a portable exe or the default per-user install to %LOCALAPPDATA%; in Tauri this means `nsis.installMode = "perMachine"`. Confidence: 0.7
- Cross-compiles Windows builds from Arch Linux using the MinGW GNU target (`x86_64-pc-windows-gnu`), so Windows packaging/tooling must be resolvable on a Linux host (e.g., the bundler invokes a native `makensis` binary rather than expecting Windows). Confidence: 0.7
- Avoids full React component re-renders on every keystroke: toolbars subscribe to derived editor state (`useEditorState` with deep equality) wrapped in `memo`, context values are memoized with `useMemo`, data/action context hooks are split so consumers only re-render on what they use, and global keydown effects read state through refs to keep dependency arrays minimal. Confidence: 0.8
- Code-splits the frontend by lazy-loading heavy views and libraries (`React.lazy` + `<Suspense>`), and uses a function-based Vite `manualChunks` matcher rather than a specifier-object so vendor runtimes (e.g., React's JSX runtime) don't get merged into feature chunks and pulled eagerly into the entry shell. Confidence: 0.8
- Prefers incremental index updates over full rebuilds on mutations (delete affected IDs + re-index only changed files) and batches many writes/deletes into a single commit instead of committing per document. Confidence: 0.8
- In async Rust, never holds a lock across `.await`: performs blocking I/O (file reads, metadata) first and takes the mutex only to apply the result; heavy startup work (e.g., a full search-index rebuild) is moved to `spawn_blocking`. Confidence: 0.75
- Shrinks search-index memory/disk footprint by indexing full content as `TEXT` (searchable) without `STORED`, and storing a truncated `preview` field for display instead of duplicating full document bodies. Confidence: 0.7
- Precompiles hot-path regular expressions as top-level `val`s rather than constructing `Regex(...)` inline per call, since each inline construction recompiles a `Pattern`. Confidence: 0.7
- Sends binary payloads (e.g., pasted images) across IPC/FFI as raw byte arrays rather than base64 strings to avoid the extra encode/decode and double memory. Confidence: 0.7
- Caches expensive-to-construct singletons (e.g., `EncryptedSharedPreferences` + `MasterKey`) in a lazy volatile field instead of rebuilding them on every getter call. Confidence: 0.7
- Treats persisted derived data (e.g., tantivy search indexes) as disposable and version-tolerant: when a schema change makes on-disk data incompatible, detect the mismatch on open (e.g., differing field count) and transparently rebuild it instead of panicking at startup — derived data is regenerable from source, so a wipe-and-rebuild is always safe. Confidence: 0.6
- Wraps every `React.lazy` component in a `<Suspense>` boundary (a `null` fallback is acceptable for always-mounted palettes/modals that only render visibly when opened): a lazy component rendered without a surrounding Suspense boundary throws and unmounts the whole tree, producing a blank/black screen. Confidence: 0.7
- When making optimization/refactor changes, verifies at runtime (the app actually launches and renders, key flows work) before reporting the work done — compile/type-check/unit-test passing is not sufficient. Introducing a crash or blank/black screen while optimizing is treated as a regression the user reports as "you broke it", so runtime verification is a required step rather than an afterthought. Confidence: 0.7
- When the user reports a regression, isolates it by diffing the last-known-good commit against the broken commit (`git diff <good> <bad>`) to see exactly which change broke it rather than guessing or re-auditing everything; the user supplies the working/broken commit hashes to bound the search. Confidence: 0.7
- In Rust filesystem traversal (vault scans) on Android, never relies on `DirEntry::file_type()` (readdir's `d_type`) to distinguish directories from files: on SAF/FUSE filesystems it returns `DT_UNKNOWN` for directories, silently skipping subfolders. Uses a single `entry.metadata()` stat with `is_dir()`/`is_file()` instead, which is reliable across filesystem types. Confidence: 0.7
- Treats vault load and explicit refresh as authoritative re-scans of the filesystem rather than reads of an in-memory cached index, so externally-added files (e.g., new files in subfolders) appear immediately; a refresh that returns a stale cache is reported as broken. Confidence: 0.6
