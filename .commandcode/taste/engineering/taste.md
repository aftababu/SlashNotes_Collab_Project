# Engineering Taste

- Eliminates disk I/O from UI rendering paths: cache file metadata (e.g., note headers, last-modified timestamps) in an in-memory index and render list items synchronously from cache, rather than per-item `File` stat calls inside composables (which cause recomposition lag/frame drops). Confidence: 0.85
- Runs all blocking/native calls (UniFFI/JNI, file system access) strictly inside `withContext(Dispatchers.IO)` — never on the main thread. Confidence: 0.95
- Invalidates in-memory caches on every mutation so cached data never goes stale after create/rename/delete/move operations. Confidence: 0.7
- Debounces and caches expensive per-keystroke work (e.g., markdown parsing) in an LRU keyed by content hash on a background dispatcher; the UI thread only does cheap cache lookups so typing and navigation never block. Confidence: 0.85
- Flattens and virtualizes large tree/list UIs into a single LazyColumn with lazy child loading instead of eager recursive nested composition, so only visible rows are composed. Confidence: 0.8
- Before changing rendering/parsing code, benchmarks or measures the actual cost (e.g., timing the Rust parser on a large document) to confirm which path is the bottleneck, rather than guessing. Confidence: 0.75
- Prioritizes config-level and build-system optimizations (R8/ProGuard minification, Rust LTO + strip + panic=abort, removing unused dependencies) before code-level micro-optimizations, because config changes carry near-zero regression risk and often yield the largest byte/RAM savings per effort spent. Confidence: 0.75
- Wants complete, untruncated, and actionable error messages with contextual detail (e.g., the file/repo path, the underlying cause, and the specific HTTP status code with what it means) so the user can self-diagnose what went wrong; generic or opaque messages (e.g., "connection failed or git not available") are reported as defects to fix. Confidence: 0.8
- Never swallows or replaces exceptions with a generic fallback message; propagates the real underlying error (including stripping framework wrappers like UniFFI's `msg=` prefix) so the user can see exactly what failed instead of a vague catch-all. Confidence: 0.75
- Maps raw error codes to actionable, human-readable hints (e.g., HTTP 401 → bad/missing token, 403 → insufficient scope or wrong URL, 404 → repo not found, 429 → rate limit, 5xx → server error) rather than surfacing raw library error text alone. Confidence: 0.75
- Keeps credential/auth handling consistent across all code paths (e.g., GitHub PATs always authenticate as `x-access-token`), so test/probe paths behave identically to the real sync path and don't produce divergent results. Confidence: 0.7
- Debugs Android issues via adb/logcat and expects errors to be logged visibly there; a failure with nothing showing in logcat is itself treated as a problem to diagnose. Confidence: 0.65
- Converts Android SAF `content://` URIs to absolute POSIX paths before passing paths through the UniFFI bridge to native code (Rust/libgit2), because native code cannot process `content://` URIs — raw URIs must never reach the native layer. Confidence: 0.9
- Validates directories before handing them to native code: ensures existence (mkdirs if missing), `isDirectory`, and `canWrite`, failing fast with an explicit user-facing error and stopping execution rather than letting native code fail opaquely. Confidence: 0.8
- Logs the exact normalized value at the FFI/UniFFI boundary so invalid inputs (e.g., raw `content://` URIs) can be confirmed to never silently reach native code. Confidence: 0.8
- Prefers embedded native libraries (e.g., libgit2 via git2 crate) over shelling out to external CLI binaries, since CLIs like `git` may not exist on Android. Confidence: 0.85
